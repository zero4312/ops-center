# ops-center 运维中台

面向运维团队的多云测试环境资源管控平台。把分散在多个云账号下的 ECS、RDS 资源收敛到统一入口，按「应用」维度纳管、展示与操作，提供一键开关机、定时开关机和账号分权管理。

> 当前覆盖：阿里云（多账号）、火山引擎（单账号）；资源类型：ECS、RDS。

## 功能一览

- **资源纳管**：通过 AK 接入多个云账号，自动拉取 ECS / RDS 实例，统一展示
- **应用分组**：按实例名称自动解析应用归属，顶部下拉框一键切换应用视角
- **一键开关机**：手动批量操作，按依赖顺序执行（开机 RDS→ECS，关机 ECS→RDS），操作前预检拦截
- **定时开关机**：按 cron 表达式设置定时策略，平台内本地调度，自动执行
- **账号系统**：admin / operator / readonly 三角色，分发给不同运维人员
- **审计日志**：登录、开关机、同步、策略变更全程留痕（开关机审计列出具体实例名）
- **系统设置**：在「系统管理」下配置每日自动同步资源状态的时间点（支持多个、可限定工作日），保存即生效无需重启
- **会话自动对账**：每日自动同步后，检测到实例已全部停机的「开机会话」自动归档到「已关闭」，消除任务中心与资源清单的状态分歧

---

## 每日自动同步（资源状态刷新）

平台内置调度器（APScheduler）按配置的时间点**每日全量拉取各云账号 ECS / RDS 最新状态**，前端资源清单、概览、任务中心据此刷新。

- **配置方式（任选其一）**：
  1. 页面配置：进入「系统管理 → 系统设置」，添加多个 `HH:MM` 时间点，可勾选「仅工作日」。
  2. 环境变量：`.env` 中 `OPS_SYNC_CRON`，多个 cron 以英文分号 `;` 分隔，例如：
     ```
     OPS_SYNC_CRON="0 9 * * 1-5;45 17 * * 1-5"
     ```
     含义：工作日 09:00 与 17:45 各同步一次。
- 页面保存即**即时重建调度（无需重启服务）**；环境变量修改需重启生效。
- 同步完成后自动触发「会话对账」（见下文任务中心说明）。

> 自动同步与「定时开关机」是两套独立机制：前者只刷新资源状态，后者按策略真实下发启停。

## 登录

浏览器访问服务地址（默认 `http://<主机>:8000`），使用分配的账号登录。

- 首次部署会创建默认管理员，账号见部署配置（默认用户名 `admin`）
- 登录后请及时修改初始密码、补充个人信息

## 界面总览

登录后左侧是功能菜单，顶部是**应用切换下拉框**：

| 菜单 | 说明 |
|---|---|
| 概览 | 当前应用的资源总量、运行/停止分布、停机可省统计 |
| 资源清单 | 按条件筛选、查看所有资源明细与状态 |
| 已释放资源 | 云上已删除资源的留痕记录（仅查看，含释放时间） |
| 任务中心 | 查看开关机任务的执行进度与结果 |
| 定时开关机 | 创建 / 启停 / 查看定时策略与执行日志 |
| 系统管理 → 系统设置 | 配置每日自动同步资源状态的时间点（仅工作日可选） |
| 云账号 | 接入云账号（AK）、连接测试、触发同步 |
| 用户与权限 | 管理运维账号（仅管理员） |
| 审计日志 | 查看操作留痕 |

**顶部下拉框是全局应用过滤器**：切换后概览、资源清单、定时策略、任务中心会同步切换为该应用的视图。下拉框始终包含「全部」与「未分类」两个固定项，「未分类」用于收纳实例名不符合命名规范的资源。

## 资源清单

- 支持按**应用、环境、账号、资源类型（ECS/RDS）、运行状态**多条件筛选
- 支持关键词搜索实例名称 / IP / 实例 ID
- 表格展示：实例名、类型、所属账号、地域、规格、计费方式、运行状态、IP、应用归属
- **「停机可省」列**是关键标记：
  - `可省`：停机能节省费用（如按量付费 ECS 节省停机、符合暂停条件的 RDS）
  - `不可省`：停机不省钱（如包年包月 ECS、不满足暂停条件的 RDS）
  - `未知`：未能判定，建议人工确认

## 已释放资源（云上已删除的留痕）

云上被删除的资源不会从平台物理删除，而是自动从「资源清单」移出并保留在「资源视图 → 已释放资源」中，仅作记录、不可操作，也**不写入审计日志**（记录本身已说明其含义）。

- **自动检测**：任意一次刷新行为发现云上已无该实例，即触发归档：
  - 每日自动同步 / 手动「云账号」同步
  - 单资源刷新、批量刷新状态
  - 开关机后的轮询状态回刷
- **归档动作**：置 `deleted_on_cloud=True` 并记录 **释放时间（released_at）** = 本次刷新检测到的时间点；资源清单与概览默认不再展示该资源。
- **恢复**：若同名实例后续重新出现在云上（如重建），释放时间会被清空、资源重新回到「资源清单」。
- 已释放视图展示：实例名、类型、云账号、应用、实例 ID、释放时间、上次同步时间，按释放时间倒序。

## 一键开关机

1. 在「资源清单」勾选目标资源（可跨应用、跨账号、跨类型混选），或直接在应用视图下对整个应用操作
2. 点击「开机」或「关机」
3. 系统弹出**预检确认框**，列出：
   - 可直接执行的资源
   - 会被跳过的资源及原因（如资源已处于目标状态、不满足停机条件、已排除纳管等）
4. 确认后任务进入「任务中心」异步执行，页面轮询展示进度

**执行顺序**（保证依赖正确）：
- 开机：RDS → ECS
- 关机：ECS → RDS

**注意**：开关机使用云账号 AK 直接调用云 API，需要账号具备对应资源的启停权限（只读 AK 无法执行）。

## 定时开关机

1. 进入「定时开关机」，点击「新建策略」
2. 配置：
   - 名称、动作（开机 / 关机）
   - 作用范围：整个应用 / 指定资源
   - cron 表达式（5 段标准 cron，时区固定为 Asia/Shanghai）
   - 失效时间（可选，到期自动停用）
3. 保存后策略即生效，列表展示**下次执行时间**与**最近执行结果**
4. 可随时启停、编辑、删除策略；每次触发都会生成执行日志

cron 示例：

| 表达式 | 含义 |
|---|---|
| `30 8 * * 1-5` | 工作日每天 08:30 |
| `0 20 * * *` | 每天 20:00 |
| `0 9 * * 1` | 每周一 09:00 |

## 系统设置（系统管理）

进入「系统管理 → 系统设置」，首个功能为**配置每日自动同步资源状态的时间点**：

- **更新时间点**：可添加多个 `HH:MM`（24 小时制）时间点，删除至至少保留 1 个
- **仅工作日**：开关开启后仅周一至周五执行（周末跳过）
- **保存即生效**：写入后立即重建内置调度器，**无需重启服务**；页面下方展示「下次执行时间（北京时间）」预览
- 配置同时持久化到数据库（DB 优先，回退 `.env` 的 `OPS_SYNC_CRON`）

## 任务中心

查看开关机任务的执行进度与结果，按状态分为「运行中 / 已关闭」区块。

- 手动或定时触发开关机后会生成任务，每项资源对应一条子项，展示成功 / 失败 / 跳过
- 在「资源清单」直接关机时，若对应开机会话仍在「运行中」，会在**下一次每日自动同步后自动归档**：
  - 判定规则：会话下**全部**目标实例均已 `stopped`（或在云上已释放）才归档到「已关闭」
  - 只要任一实例仍在运行，会话保持「运行中」
  - 归档时会生成一条 `system(sync-reconcile)` 留痕 stop 任务并写入审计，便于追溯

## 云账号管理（管理员）

1. 「云账号」→「添加云账号」
2. 填写：账号名称、云厂商（阿里云 / 火山引擎）、地域、AccessKey ID、AccessKey Secret、备注
3. 保存后先点「连接测试」验证 AK 可用性与权限
4. 连接测试通过后点「同步」，系统自动拉取该账号下的 ECS / RDS 并解析应用归属

**安全要求**：
- 禁止使用主账号 AK
- 应为每个被纳管账号创建独立 RAM 子用户，仅授予 ECS / RDS 只读 + 启停所需的最小权限
- AK/SK 加密后存储在数据库中

## 用户与权限（管理员）

「用户与权限」中可创建 / 编辑 / 停用运维账号，分配角色。

| 角色 | 权限范围 |
|---|---|
| **admin（管理员）** | 全部权限：含云账号管理、用户管理、资源同步、开关机、定时策略 |
| **operator（运维）** | 执行开关机、管理定时策略、资源同步、查看资源 |
| **readonly（只读）** | 仅查看资源、任务、策略、审计，不可执行任何写操作 |

## 审计日志

记录所有关键操作：登录、开关机、资源同步、云账号增改、策略增改、用户增改、每日对账等，含操作人、对象、结果、来源 IP、时间。

- 开关机（start / stop）审计的「对象」列展示**具体操作的具体实例名清单**（如 `apc-app-test-web-01(ecs)、apc-app-test-db-01(rds)`），而非笼统的「N 个资源」，便于精确追溯
- 会话自动对账产生的归档同样会写入审计，操作人为 `system(sync-reconcile)`

## 部署与运维须知

- **自动建表 / 补列（自愈迁移）**：服务启动时自动检测并补齐缺失的表列（如 `operation_tasks.closed_at`、`close_task_id`、`cloud_accounts.last_sync_msg`），无需手动执行 DDL；历史上因升级未跑迁移导致的 `Unknown column` 报错已通过此机制根治
- **日志时间戳**：所有 uvicorn 及业务日志默认带 `%(asctime)s` 时间戳，便于按时间定位问题
- **部署脚本**：`deploy.sh` 支持一键安装 / 启动 / 重启（本机或云服务器），`uvicorn --workers 1` 运行；Docker 拉起 MySQL 时自动注入数据库连接环境变量
- **数据库**：默认 MySQL 8（本地 Docker 或云上 RDS，仅改连接串）；也支持 SQLite 快速体验（改 `.env` 的 `OPS_DATABASE_URL`）
