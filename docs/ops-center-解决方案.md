## 1. 定位与需求

### 1.1 平台定位

**运维中台**：把分散在多个云账号、多个云厂商的测试环境资源收敛到一个统一入口，向上为运维和研发提供一致的视图与操作，向下屏蔽各云厂商 API 差异。平台自身不重复造云厂商已经提供的能力（如定时调度），而是**编排与聚合**。

### 1.2 首批功能范围（逐条对应）

| # | 需求 | 本方案实现方式 | 章节 |
|---|---|---|---|
| 1 | 管理多账号下 ECS、RDS，实现开关机 | 多云账号接入 → 资源同步 → 应用维度一键开关机 | 5.1 / 5.3 |
| 2 | 定时开关机调用云厂商原生能力 | **阿里云 → OOS（`ACS::TimerTrigger` 定时执行）**；**火山引擎 → 见 2.2 差异说明** | 2 / 5.4 |
| 3 | 账号系统，分发给运维人员 | 用户 + 角色 + 应用级数据权限 + 审计 | 5.5 |
| 4 | 通过接入 AK 增加管理账号 | 账号管理模块，随时新增，AK 加密存储 | 5.1 |
| 5 | 资源按应用分组，下拉框切换 | 应用为主维度，顶部下拉框切换，资源随之过滤 | 5.2 |

### 1.3 本期不做

- CLB / SLB（咨询部已明确本期不含）
- 资源开通、变配、删除等高危操作
- 生产环境资源纳管
- CI/CD、监控大盘、告警中心（均预留扩展点）
- 成本金额统计（本期只做停机时长，金额估算放二期）

## 2. 定时开关机方案：云厂商原生能力核实

这是本次方案变更中**技术风险最高**的部分，先给核实结论，再给设计。

### 2.1 阿里云 OOS —— 可行

| 核实项 | 结论 |
|---|---|
| OOS 是否支持定时执行 | 支持。`ACS::TimerTrigger` 动作，类型支持 `cron` / `at` / `rate`，可指定 `TimeZone: Asia/Shanghai` |
| 是否支持 ECS 批量开关机 | 支持。公共模板 `ACS-ECS-BulkyStartInstances` / `ACS-ECS-BulkyStopInstances`，动作 `ACS::ECS::StartInstance` / `StopInstance`，支持 `stoppedMode`（KeepCharging / StopCharging）、`forceStop`、速率控制 |
| **是否支持 RDS 批量开关机** | **支持。** 动作 `ACS::RDS::StartInstance` / `ACS::RDS::StopInstance`，公共模板 `ACS-RDS-BulkyStartInstances` / `ACS-RDS-BulkyStopInstances` |
| 官方「定时开关机」功能 | OOS 控制台「常用运维任务 > 定时开关机」原生支持 ECS 与 RDS，可选每天/指定时间、先开机再关机或先关机再开机、三种停机模式 |
| 能否通过 API 管理 | 可以。OOS 提供完整 OpenAPI：`StartExecution` / `CancelExecution` / `ListExecutions` / `GetExecution` / `CreateTemplate` 等 |

**平台的做法**：每个阿里云账号 + 每个地域预置两个自定义模板（开机模板、关机模板），平台通过 `StartExecution` 创建定时执行，通过 `CancelExecution` 停用，通过 `ListExecutions` 拉取执行历史。

**OOS 的硬限制（必须纳入设计）**：

| 限制 | 影响 | 应对 |
|---|---|---|
| `EndDate` **必填** | 定时任务必须有终止时间，不会无限期执行 | 平台默认设 1 年；**策略到期前 7 天提醒并支持一键续期**（重建云侧执行）；页面明示"有效期至" |
| 一个模板只允许一个触发器，且必须是第一个 task | 无法在一个模板里塞多条 cron | 一条定时规则 = 一个执行。应用需要"9:00 开 + 20:00 关"就创建两个执行 |
| cron **默认按 UTC 计算** | 不指定时区会差 8 小时 | 模板固定 `TimeZone: Asia/Shanghai`，平台侧不再转换 |
| OOS 是**地域级**服务 | 跨地域资源需每个地域建一个执行 | 平台按"策略 → 地域"拆分为多条执行，聚合展示为一条策略 |
| 需要 OOS 服务角色 | 账号首次接入需授权 | 接入流程引导创建 `OOSServiceRole` 并给出最小权限策略，接入自检时校验 |
| 父执行长期处于 Waiting 状态 | 占用执行数配额 | 账号接入时检查配额；策略数量做上限提示 |

### 2.2 火山引擎运维编排 —— 能力不对等

火山引擎**确实有**「运维与监控 > 运维编排」服务，支持编排任务（立即执行 / 定时执行 / 周期执行）与编排计划（事件 / 告警触发）。但与阿里云 OOS 对比有三点关键差异：

| 对比项 | 阿里云 OOS | 火山引擎运维编排 |
|---|---|---|
| 定时 / 周期执行 | 支持 | 支持（按分钟/小时/天周期，有起止时间，时区固定 GMT+8） |
| **覆盖资源** | ECS + RDS + 众多产品 | **文档与默认角色均围绕 ECS**（默认角色 `CustomRoleForOOS` 为"云服务器 ECS 全读写权限"），**未发现 RDS 启停步骤** |
| **OpenAPI** | 完整开放 | **未检索到公开 OpenAPI**，现有文档均为控制台操作指引 |
| 批量运维任务范围 | 实例、云盘、镜像、带宽等 | 实例、云盘、镜像、临时带宽（**均为 ECS 侧**） |

> 火山 RDS 本身有 `StopDBInstance` / `StartDBInstance` API（可用），但**编排服务能否调度 RDS 步骤，以及有无 API 供平台调用，目前无法从公开文档确认**。

### 2.3 由此确定的定时开关机实现策略

**采用统一抽象 + 两种实现，对上层策略管理透明：**

```
        策略管理（统一 UI：创建 / 启停 / 查看历史）
                      │
        ┌─────────────┴─────────────┐
        │                           │
  AliyunOOSProvider          LocalSchedulerProvider
   StartExecution / Cancel     APScheduler 自建调度
   ListExecutions             + 直接调 ECS/RDS API
        │                     执行历史落本地表
   阿里云账号（全部）          火山引擎账号
```

| 云厂商 | 定时实现 | 理由 |
|---|---|---|
| **阿里云** | **托管给 OOS** | API 成熟、支持 ECS+RDS、自带速率控制与执行历史，平台不用自建调度 |
| **火山引擎** | **待 M0 验证后定** | 优先尝试其编排服务 API；**若无可用 API 或不支持 RDS，则回退平台自建调度**（APScheduler + 直接调 ECS/RDS API，约 3~4 人天） |

> 火山仅 1 个账号、资源量小，回退方案成本可控。
> **M0 必须先验证**：火山运维编排是否开放 API、是否支持 RDS 步骤。这条不定，M3 排期就不准。

## 3. ECS / RDS 开关机能力约束

约束与 v2.0 一致（已核实官方文档），本节精简保留，去掉 CLB。

### 3.1 阿里云

| 资源 | 停机 | 省钱 | 关键限制 |
|---|---|---|---|
| ECS | ✅ `StopInstances` | **看模式** | `StopCharging`（节省停机）停收计算资源费，但**计算资源回收，启动可能 `OperationDenied.NoStock` 失败**；`KeepCharging`（普通停机）**不省钱**；**包年包月不支持节省停机，调用不报错、静默退化**；仅 VPC + 按量 + 非本地盘/非持久内存规格支持；批量上限 100 |
| RDS | ✅ `StopDBInstance` | ✅ 停规格费 | **必须同时满足**：按量付费 + ESSD 云盘 + 通用型规格族 + 高可用/基础系列 + 主实例无只读 + 未开数据库代理 + 内核小版本 ≥ 20201031；**暂停上限 30 天，到期自动启动**；API 限流 **10 QPS**；暂停期间除最新一份全量备份外其余备份会过期 |

### 3.2 火山引擎

| 资源 | 停机 | 省钱 | 关键限制 |
|---|---|---|---|
| ECS | ✅ `StopInstances` | **看模式** | `StopCharging` 限按量计费（不含本地盘、弹性裸金属、HPC GPU）；启动时可能库存不足；单次上限 100；支持 `ClientToken` 幂等 |
| RDS | ✅ `StopDBInstance` | ✅ | **仅按量计费**；不支持灾备实例与蓝绿部署实例；**账户余额须 ≥ 100 元**；**最长暂停 1 个月，到期自动启动**；**暂停前系统自动触发一次全量备份**（耗时，超时需放宽） |

### 3.3 产品设计决策

| 决策 | 理由 |
|---|---|
| 资源页标注「停机可省 / 不可省」 | 包年包月 ECS、非 ESSD 的 RDS 停了不省钱甚至不能停，不标注会导致成本优化效果严重误判 |
| ECS 默认 `KeepCharging` | 测试环境"早上开机要用"优先于省钱；需省钱的应用单独开启节省停机 |
| 定时策略间隔校验 ≤ 25 天 | 规避阿里云 RDS 30 天、火山 RDS 1 个月被强制自动启动 |
| 启停依赖顺序：开机 RDS→ECS，关机 ECS→RDS | 开机先起数据层；关机先停应用层再停数据层 |
| 操作前预检拦截 | 不满足条件的资源在确认弹窗就列出，而非执行后报一堆失败 |

```
│  API 层    Python 3 + FastAPI + SQLAlchemy + Pydantic       │

└───────────────────────────────────────────────────────────┘
        │                              │

└───────────────────┘    └──────────────────────────────┘
        │                              │
┌───────────────────────────────────────────────────────────┐
│  云适配层   统一 Provider 接口                              │
│  ListResources / Start / Stop / DescribeStatus              │

│  └── VolcProvider     ECS · RDS（单账号 AK）                │
└───────────────────────────────────────────────────────────┘
                        │
┌───────────────────────────────────────────────────────────┐
│  持久化   MySQL 8 —— 唯一存储                                │
```

**相较 v2.0 的最大变化：平台自建调度器从"定时开关机"退化为"资源同步 + 兜底"。** 阿里云的定时完全托管给 OOS，平台只做创建/停用/查历史 —— 不用自己算 cron、不用自己轮询执行、不用担心进程重启导致任务丢失，这些 OOS 全包了。

## 5. 功能设计

### 5.1 云账号管理（AK 接入）

| 功能 | 说明 |
|---|---|
| 新增账号 | 表单：厂商（阿里云/火山）、账号名称、AccountID、AccessKey ID/Secret、纳管地域（多选）、启用开关 |
| AK 存储 | AES-GCM 加密落库，密钥由环境变量注入；**永不在接口返回、日志输出、前端展示中出现** |
| 连通性自检 | 保存后立即调用只读 API 验证：凭证有效？权限够吗？地域可达？OOS 服务角色已授权？ |
| 随时增补 | 新账号接入后手动触发一次全量同步，资源即刻出现在平台上 |
| 停用/启用 | 停用后不再同步、不可操作，历史数据保留 |
| AK 轮转 | 支持更换 AK 并保留历史操作记录 |

**AK 方式的安全要求（务必遵守）**：

| 要求 | 说明 |
|---|---|
| **绝不使用主账号 AK** | 必须在每个被管账号下创建 **RAM 子用户 / IAM 子用户**，仅授予平台所需最小权限 |
| 最小权限策略 | 见第 7 章，不含任何 `Delete*` / `Create*` / `Modify*` |
| 加密存储 + 环境变量注入密钥 | 密钥不入库、不入代码、不进版本库 |
| 来源 IP 白名单（推荐） | 在云厂商侧限定该 AK 只能从平台服务器 IP 调用 |
| 定期轮转 | 建议 90 天，平台提供到期提醒 |
| 全量审计 | 所有操作记录到人、到资源、到时间 |

> 若后续有条件配置跨账号 RAM 角色（STS），平台预留 `credential_type` 字段可平滑切换，**凭证获取逻辑封装在 Provider 内部，上层无感知**。

### 5.2 应用分组与资源视图（下拉框切换）

```
┌────────────────────────────────────────────────────────────┐
│  ops-center   [ 应用：订单中心-test  ▾ ]   任务中心  吕鹏 ▾ │

│  概览：ECS 6 台（运行 2 / 停止 4）  RDS 2 个（运行 1 / 停止 1）│
│        [ 一键开机 ]  [ 一键关机 ]  [ 定时策略 (2) ]          │
├────────────────────────────────────────────────────────────┤
│  [ECS] [RDS]                                                │
│  ┌──────────────────────────────────────────────────────┐  │
│  │ 实例名/ID    规格   云账号  地域  状态  可省  操作      │  │
│  │ i-xxx1      4C8G   阿里云A 杭州  ●运行  是   [关机]    │  │
│  │ i-xxx2      2C4G   阿里云B 上海  ○停止  否   [开机]    │  │
```

| 功能点 | 说明 |
|---|---|
| 应用下拉框 | 顶部全局选择器，支持搜索；切换后概览、资源清单、定时策略、任务记录全部随之过滤 |
| 应用管理 | 应用编码、名称、负责人、部门、默认停机模式、禁止自动停机开关 |
| 资源归属 | **标签自动发现 + 手工绑定双轨**，手工绑定优先；支持 CSV 批量导入绑定关系 |
| 未归属资源 | 独立页面列出尚未绑定的资源，驱动逐步收敛 |
| 可停机性标记 | 依据第 3 章约束自动计算「可停/不可停」「停机可省/不可省」并给出原因 |
| 状态实时性 | 每 30 分钟全量同步；打开页面时触发一次轻量状态刷新；单资源支持手动刷新 |

### 5.3 一键开关机

| 步骤 | 内容 |
|---|---|
| 1 前置校验 | 权限 → 应用存在性 → 资源清单 → 应用维度行锁（防重复点击） |
| 2 预检 | 逐资源校验状态机与停机条件，生成可执行清单，标注跳过项与拦截项（含原因） |
| 3 确认 | 弹窗按依赖顺序列出将要操作的资源，运维确认 |
| 4 排序 | 开机：RDS → ECS；关机：ECS → RDS |
| 5 执行 | **直接调用云 API（不走 OOS）**，按厂商批量上限分批；RDS 受 10 QPS 限流约束串行化 |
| 6 轮询 | 任务线程内每 10 秒轮询目标状态；ECS 10 分钟超时，RDS 20 分钟（火山 RDS 暂停前会自动全量备份） |
| 7 收尾 | 汇总成功/失败/跳过，写审计日志 |

> **手动开关机不经过 OOS**：手动操作要求即时反馈，直接调云 API 更简单，结果秒级可见。OOS 只用于定时场景。

**关键机制**：幂等（状态机拦截 + 火山 `ClientToken`）、并发控制（MySQL 行锁）、限流（进程内信号量 + 滑动时间窗）、重试（仅限流/5xx/短暂冲突，最多 3 次指数退避；`NoStock`、权限不足、条件不满足不重试）、部分失败可重试失败项。

### 5.4 定时开关机

**统一策略模型**（对运维只呈现一套 UI）：

| 要素 | 设计 |
|---|---|
| 作用对象 | 一个应用（下拉框当前应用） |
| 规则 | 多条，每条 = 动作（开机/停机）+ cron（时区固定 Asia/Shanghai）+ 生效资源类型（ECS/RDS/全部） |
| 停机模式 | 沿用应用级配置（KeepCharging / StopCharging） |
| 有效期 | 默认 1 年；到期前 7 天提醒并支持一键续期（重建云侧执行） |
| 安全校验 | 保存时校验停机规则与最近开机规则间隔 ≤ 25 天 |
| 执行历史 | 阿里云侧从 OOS 拉取；火山侧从本地表读取；**统一格式展示** |
| 立即执行一次 | 用于验证配置是否正确 |
| 启停 | 停用 = 取消云侧执行；启用 = 重新创建 |

**阿里云侧落地（OOS）**：平台在每个「账号 × 地域」预置两个模板，任务步骤设计如下：

| 模板 | 任务顺序 | Action | 说明 |
|---|---|---|---|
| `ops-center-start` | 1 | `ACS::TimerTrigger` | cron / TimeZone=Asia/Shanghai / EndDate |
| | 2 | `ACS::RDS::StartInstance` | 循环 RDS 实例列表，带速率控制 |
| | 3 | `ACS::ECS::StartInstance` | 循环 ECS 实例列表，带速率控制 |
| `ops-center-stop` | 1 | `ACS::TimerTrigger` | 同上 |
| | 2 | `ACS::ECS::StopInstance` | 参数含 `stoppedMode`、`forceStop=false` |
| | 3 | `ACS::RDS::StopInstance` | 关机顺序：先应用层后数据层 |

平台侧动作：创建策略 → `StartExecution`（记录 ExecutionId）→ 停用 `CancelExecution` → 查历史 `ListExecutions`。跨地域时按地域拆分为多个执行，聚合展示为一条策略。

**火山侧落地**：M0 验证后确定（见 2.3）。

### 5.5 账号与权限系统

| 项 | 设计 |
|---|---|
| 认证 | 用户名 + 密码（bcrypt 哈希）；JWT 签发与校验 |
| 角色 | **管理员**：全部权限，含账号管理与用户管理<br>**应用负责人**：可操作自己负责的应用（开关机、改定时策略），不可管账号<br>**只读**：仅查看 |
| 数据权限 | 资源可见范围按「应用负责人 + 部门」过滤；管理员可见全部 |
| 用户管理 | 增删改查、启用停用、强制改密、角色分配 |
| 密码策略 | 初始密码强制修改；复杂度要求 |
| 审计 | 记录操作人、时间、应用、资源、动作、结果、来源 IP；**不可删除，保留 ≥ 180 天** |
| 高危保护 | 单次操作资源数超阈值（默认 50）二次确认；应用级「禁止自动停机」开关 |
| 预留 | 用户表预留 `external_id` 字段，后续可对接 LDAP / 飞书扫码，不改主流程 |

## 6. 数据模型

## 7. 云凭证与最小权限

### 7.1 阿里云 RAM 子用户策略

在被管账号下创建 RAM 子用户，授予自定义策略，**仅包含**：

| 服务 | 只读 | 写 |
|---|---|---|
| ECS | `ecs:DescribeInstances`、`ecs:DescribeRegions` | `ecs:StartInstance`、`ecs:StopInstance`、`ecs:StartInstances`、`ecs:StopInstances` |
| RDS | `rds:DescribeDBInstances`、`rds:DescribeDBInstanceAttribute` | `rds:StopDBInstance`、`rds:StartDBInstance` |
| OOS | `oos:GetTemplate`、`oos:ListTemplates`、`oos:ListExecutions`、`oos:GetExecution`、`oos:ListTaskExecutions` | `oos:StartExecution`、`oos:CancelExecution`、`oos:CreateTemplate`、`oos:UpdateTemplate` |

> 不含任何 `Delete*` / `Create*` / `Modify*` 资源类操作。另需为 OOS 创建服务角色 `OOSServiceRole` 并授予上述 ECS/RDS 写权限。

### 7.2 火山引擎 IAM 子用户策略

- ECS：`ecs:DescribeInstances`、`ecs:StartInstance` / `StartInstances`、`ecs:StopInstance` / `StopInstances`
- RDS：`rds_mysql:DescribeDBInstances`、`rds_mysql:StopDBInstance`、`rds_mysql:StartDBInstance`
- 若火山侧走编排服务，另行追加编排相关权限（M0 验证后确定）

## 8. 技术选型

沿用 v2.0，无 Redis：

| 层 | 选型 |
|---|---|
| 前端 | Vue 3 + Element Plus + Vite + Pinia |
| 后端 | Python 3.11 + FastAPI + SQLAlchemy 2.0 + Alembic + Pydantic |
| 认证 | PyJWT + bcrypt |
| 数据库 | MySQL 8（唯一存储） |
| 调度器 | APScheduler 3.x（BackgroundScheduler + SQLAlchemyJobStore + ThreadPoolExecutor），**仅用于资源同步与火山侧兜底** |
| 并发控制 | MySQL `SELECT ... FOR UPDATE` 行锁 |
| 限流 | 进程内 `threading.Semaphore` + 滑动时间窗 |
| 云 SDK | 阿里云 `alibabacloud-ecs20140526` / `rds20140815` / `sts20150401` / `oos20190601`；火山 `volcengine-python-sdk` |
| 凭证加密 | `cryptography`（AES-GCM），密钥环境变量注入 |
| cron | `croniter`（校验 + 下次执行时间预览） |

**部署**：`uvicorn --workers 1`（必须为 1，否则 APScheduler 重复执行）+ MySQL 两容器，systemd 或 Docker Compose。

## 9. 风险登记

| # | 风险 | 影响 | 应对 |
|---|---|---|---|
| R1 | ECS 节省停机后库存不足启动失败 | 早上开机失败 | 默认 KeepCharging；失败重试 + 立即通知；提供强制开机应急入口 |
| R2 | RDS 暂停满 30 天 / 1 个月被自动启动 | 状态与费用失控 | 策略间隔校验 ≤25 天；每日同步校正；暂停超 20 天预警 |
| R3 | 包年包月资源停机仍计费 | 成本效果不达预期 | 资源页标注「停机不可省」 |
| R4 | 误操作影响生产 | 严重事故 | 仅接入测试账号；最小权限；大批量二次确认；应用级禁止自动停机 |
| R5 | 云 API 限流 | 操作超时 | 令牌桶限流 + 排队 + 重试；RDS 串行化 |
| R6 | 状态漂移（有人在控制台手动改了） | 平台显示与实际不符 | 30 分钟全量对账；操作前实时查一次真实状态 |
| R7 | **AK 泄露** | 云资源被非法控制 | 只用子用户 AK + 最小权限 + AES-GCM 加密 + IP 白名单 + 定期轮转 + 全量审计 |
| R8 | 火山 RDS 账户余额 < 100 元 | 暂停/启动失败 | 操作前余额预检；失败明确归因 |
| R9 | **OOS 执行 EndDate 到期后静默失效** | 定时策略悄悄停止 | 默认 1 年；到期前 7 天提醒；页面明示有效期；一键续期 |
| R10 | **OOS 跨地域需建多个执行** | 策略管理复杂度上升 | 平台按地域拆分并聚合展示；策略详情页列出各地域执行状态 |
| R11 | **火山运维编排无 API 或不支持 RDS** | M3 排期失控 | **M0 优先验证**；回退自建调度（约 3~4 人天） |
| R12 | 单实例重启导致任务中断 | 任务卡 running | 启动扫描超时任务，回查云端真实状态修正；30 分钟同步兜底 |
| R13 | `uvicorn --workers > 1` | 定时任务重复执行 | 固定 1；启动自检告警；数据库唯一索引兜底 |

## 10. 实施计划

| 里程碑 | 目标 | 主要交付 | 周期 |
|---|---|---|---|
| **M0 技术验证** | 把不确定项打掉 | ① 火山运维编排是否有 OpenAPI、是否支持 RDS 步骤<br>② 阿里云 OOS 自定义模板 + `StartExecution` 全链路验证<br>③ 多账号 RAM 子用户 AK 连通性与权限验证<br>④ OOS 执行数配额确认 | **2~3 天** |
| **M1 账号、资源与权限** | 看得见、分得清、谁都能用 | 项目骨架 → 账号管理（AK 接入 + 自检）→ 资源同步引擎 → 应用管理 → 资源绑定（CSV 导入）→ 应用下拉切换视图 → 用户/角色/权限 → 登录 | 2 周 |
| **M2 一键开关机** | 手动操作跑通 | 云适配层（ECS/RDS × 阿里云/火山）→ 任务表与状态机 → 依赖顺序编排 → 预检拦截 → 状态轮询 → 审计日志 → 任务中心页 | 1.5 周 |
| **M3 定时开关机** | 自动化跑通 | 阿里云 OOS 适配器（模板预置 + 执行生命周期管理）→ 火山侧（按 M0 结论）→ 策略管理页 → 25 天与有效期校验 → 执行历史聚合展示 | 1.5 周 |
| **M4 加固与交付** | 可交付运维使用 | 权限细化 → 异常与中断恢复 → 部署脚本 → 运维手册 → 培训 | 1 周 |

**合计约 6.5 周**（含 M0）。

> **M0 必须先行**。火山侧能力不确定、OOS 模板链路未验证，这两件事不定，M3 就排不准，整个计划有返工风险。
